# lhg-email-deliver：送达率 checklist

> 目标：邮件发出后进的是收件箱，不是垃圾箱。
> 核心纪律：**内容层的问题用脚本扫，基础设施的问题用清单问 —— 本 skill 不碰发信基础设施，只给方法论和检查项。**

## 1. 何时使用

- 邮件稿写完，准备发出 → 先跑第 2 步脚本 + 第 4 节人工项
- 打开率突然腰斩 → 按第 5 节排查
- 换发信工具/换域名 → 重走第 4 节全部项

## 2. 第一步：跑确定性审计脚本（必做，零成本）

在项目根目录执行插件自带的审计脚本（用你所在平台执行本地脚本的方式）：

```
python3 <插件目录>/scripts/audit/email_audit.py --target <邮件稿目录>
```

- 脚本含 12 条规则：无退订链接（blocker）、垃圾触发词、标题超长/emoji 滥用/全大写、无纯文本版、链接无追踪参数、无发件人地址等。
- 有 blocker 时脚本以非零 exit code 退出 —— 这是设计，不是 bug。
- `--fail-on` 控制 exit code 语义：默认 `blocker`；想要更严可设为 `warning`。

## 3. 第二步：分级与修复

| 级别 | 定义 | 处理 |
|---|---|---|
| blocker | 合规红线：无退订链接 | 必须修，不修不许定稿（commit 前的 hook 会拦截） |
| warning | 大概率进垃圾箱：垃圾词、标题超长、无纯文本版、无 utm、无发件人地址 | 本次修掉；修不掉写理由+有效期进报告 |
| nit | 洁癖项：图片无 alt、无预览文本 | 顺手修 |

**修不掉的 blocker**：列进报告「需人工处理」区，**不许**为清零改规则或阈值 —— 那是作弊。

## 4. 第三步：人工检查项（脚本抓不到的，逐项打勾）

### 身份认证三件套（去 DNS 查，不要信"我觉得配了"）

- [ ] **SPF**：`dig TXT 你的域名` 能看到 `v=spf1 ...` 记录，且包含了你的发信服务商
- [ ] **DKIM**：发信服务商后台显示 DKIM 已验证（selector 记录已加到 DNS）
- [ ] **DMARC**：有 `v=DMARC1` 记录，起步用 `p=none`（只监控），稳定后再收紧

### 发信域名与预热

- [ ] 用独立子域名发信（如 `mail.你的域名`），别用主域名裸发 —— 主域名进黑名单是灭顶之灾
- [ ] 新域名/新 IP 慢慢预热：第一周每天几百封，逐周加量；第一天发 1 万封等于自杀
- [ ] 发信量稳定，别今天 100 封、明天 5 万封 —— 忽高忽低是垃圾邮件的典型特征

### 合规（各国法律，出海必看）

- [ ] 每封营销邮件底部有**一键退订链接**（CAN-SPAM / GDPR / 中国《互联网电子邮件服务管理办法》都要求）
- [ ] 退订链接点进去**真的能退订**（自己测一遍，别只摆个样子）
- [ ] 英文邮件底部有**物理地址**（CAN-SPAM 要求：公司名+地址）
- [ ] 退订后 10 个工作日内生效（CAN-SPAM），最好做到即时生效
- [ ] 只给「明确同意接收」的人发（ double opt-in 最稳）

### 列表卫生

- [ ] 硬弹（不存在的邮箱）自动清理已开启
- [ ] 6 个月零打开的用户已移出营销列表（或降频）
- [ ] 没有买来的名单（再说一遍：买名单=主动申请进垃圾箱）

## 5. 第四步：打开率暴跌排查（按顺序查）

1. 先看是不是**全量跌**还是**某几封跌**：全量跌 → 查基础设施（认证/黑名单）；某几封跌 → 查内容（标题/垃圾词）。
2. 查域名/IP 是否进黑名单（MXToolbox 这类公开查询）。
3. 查最近有没有换发信工具、换域名、突然加量。
4. 查投诉率：超过 0.1% → 停发，查列表来源。
5. 内容回滚：对比暴跌前后改了什么（新模板？新标题风格？）。

## 6. 诊断报告模板

```markdown
# 邮件送达率诊断报告（YYYY-MM-DD）
- 邮件：<名称/批次>
- 审计：blocker=X warning=Y nit=Z（脚本输出附后）
- blocker 处理：<逐条说明修了 / 列入需人工处理>
- warning 豁免：<理由 + 有效期>
- 人工项：SPF/DKIM/DMARC <通过/未配>；发信域名 <子域名>；预热状态 <...>
- 合规：退订链接 <有/实测通过>；物理地址 <有/无>
- 结论：通过 / 不通过
```

## 9. 黑名单与申诉（真进去了怎么办）

1. **确认**：用公开黑名单查询工具查你的发信域名/IP，确认在哪家黑名单上。
2. **自查**：对照第 4 节找原因（投诉率高？买名单？没预热？），原因不改申诉也没用。
3. **申诉**：去该黑名单官网走 delist 流程，如实说明整改措施（如"已清理列表、加上 double opt-in"）。
4. **等待**：一般 24-72 小时，别重复提交。
5. **复发**：同一原因进两次，申诉会越来越难 —— 所以第 1 步自查最重要。

**预防大于申诉**：认证三件套 + 列表卫生 + 慢慢预热，做到这三条基本不会进。

## 10. 发信工具选型参考（只给思路，不代购）

| 场景 | 常见选择 | 备注 |
|---|---|---|
| 刚起步、量小 | Mailchimp / Brevo 免费档 | 先验证模式，别急着付费 |
| 电商自动化 | Klaviyo | 加购挽回、序列自动化最强，但贵 |
| 预算敏感 | Brevo / Amazon SES + 自建 | 便宜，但自动化和模板要自己搭 |
| 国内出海 | 选支持中文客服的 | 出问题时能找到人比便宜 10% 重要 |

**选型三问**：自动化够不够用？送达率口碑如何？超量后单价多少？—— 按这个顺序问。

## 11. 反模式（不要这么干）

- ❌ 没跑脚本就说「能发了」—— 机器 5 秒能抓的硬伤，别用人眼赌
- ❌ 新域名第一天发 1 万封 —— 预热是铁律
- ❌ 退订链接摆设（点了退不掉）—— 被投诉一次，罚的比赚的多
- ❌ 主域名裸发营销邮件 —— 进黑名单连官网邮箱一起完蛋
- ❌ 打开率跌了就加量「补回来」—— 越发越进垃圾箱，恶性循环
- ❌ 为清零改脚本规则 —— 作弊，不是诊断

## 12. 误报处理

规则是启发式，一定会误伤。误报不可怕，乱处理才可怕：

1. **判断三问**：这封邮件真的有问题吗？这条规则的本意是什么？按规则改了会不会伤害转化？
2. **确认误报**：在稿件顶部加一行注释说明原因（如 `<!-- 纯通知邮件，无营销内容 -- 豁免 EM-CMP-002 -->`），并记入报告的豁免清单。
3. **拿不准**：按 warning 处理，不要直接忽略。
4. **规则本身有问题**：附最小复现稿件提 issue（见第 14 节），说明"期望行为"，不要自己改脚本阈值。

**注意**：EM-CMP-001（无退订链接）不接受"误报"豁免 —— 只要是营销邮件，就必须有退订链接。

## 13. 送达率月度复盘模板

```markdown
# 送达率月度复盘（YYYY-MM）
- 发送量 / 打开率 / 点击率 / 退订率 / 投诉率（环比上月）
- 认证三件套状态：SPF ✅ DKIM ✅ DMARC ✅/❌
- 本月最高/最低打开率的邮件各一封，原因分析
- 列表变化：新增 X，退订 Y，清理沉睡 Z
- 下月动作：<1-2 个最该做的事>
```

每月花 30 分钟填完这张表，送达率就不会悄悄死掉。

## 14. 自检与反馈

每次执行完本 skill，做一次轻量自检：

1. 脚本是否真的跑了（而不是「我觉得没问题」）？→ 没跑不算做
2. blocker 是否清零或全部列入「需人工处理」？→ 有遗漏就补
3. 人工检查项是否逐项打勾？→ 打勾要有依据（DNS 查询结果、实测截图）
4. 合规三项（退订/地址/同意）是否全过？→ 没过的不许发

标准冒烟用例：对插件自带的 `fixtures/` 跑脚本，确认坏 fixture 的埋点规则全命中、好 fixture 零 blocker（见仓库根 `smoke_test.py`）。

反馈渠道：以 `[QC] <一句话问题>` 为标题提交到 https://github.com/lhg-plugs/lhg-email/issues，正文写清「输入 → 错误输出 → 期望输出」。规则误报/漏报请附最小复现代码。

**边界重申**：本 skill 只覆盖方法论与内容层。DNS 记录配置、发信服务器搭建、IP 预热执行由用户或其发信服务商完成，不在本插件范围内。
