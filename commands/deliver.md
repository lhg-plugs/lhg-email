# /lhg-email:deliver —— 送达率诊断

用户输入在 `$ARGUMENTS` 中：`[邮件稿目录] [--fix]`。目录缺省为当前项目根目录。

## 流程（加载 lhg-email-deliver 全程指导）

### 1. 跑脚本
```bash
python3 ${CLAUDE_PLUGIN_ROOT}/scripts/audit/email_audit.py --target <目录> --format text
```
记下 blocker / warning / nit 的数量与明细（含文件、行号、规则说明）。

### 2. 分级与修复
- **blocker**（无退订链接）：逐条修。`--fix` 缺省即自动修（加标准退订块）；修不掉的列入「需人工处理」，不许为清零改规则。
- **warning**（垃圾触发词、标题超长/emoji 滥用、无纯文本版、链接无追踪参数、无发件人地址）：修掉或写豁免理由（+有效期）；**nit**：顺手修。

### 3. 人工复核（脚本抓不到的，见 lhg-email-deliver 第 4 节）
- SPF / DKIM / DMARC 配了吗？（去 DNS 查，不要信"我觉得配了"）
- 发信域名是独立子域名吗（如 `mail.你的域名`）？别用主域名裸发
- 发信量是慢慢预热的吗？新域名第一天发 1 万封等于自杀
- 退订链接点进去真的能退订吗？（自己测一遍）

### 4. 输出报告
按 lhg-email-deliver 第 6 节模板输出诊断报告，结论写清「通过 / 不通过」。

## 硬规则
- 无退订链接就说「通过」→ 不许，这是合规红线（CAN-SPAM / GDPR 罚款不是开玩笑）。
- 为清零改脚本规则或阈值 → 这是作弊，不许。
- 本命令只诊断内容层，**不碰发信基础设施**（DNS 配置、发信服务器由用户或服务商处理）。
